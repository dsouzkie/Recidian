Business Cost Optimization — Threshold Sweep

We swept 99 thresholds from 0.01 to 0.99, assigning INR 2,150 to each False Positive (good customer blocked) and INR 1,085 to each False Negative (missed fraud). The optimal threshold of 0.69 minimizes total business loss to INR 36,550 on the test set.

Transparency & Methodology Disclosure

⚠️ What's Simulated

The Razorpay demo uses pay_mock123 as payment ID because programmatic card capture requires a client-side checkout UI with real card entry. All Order IDs (e.g. order_TWprJiPLrXJE4B) are genuine Razorpay test-mode API calls verifiable in the Razorpay dashboard. The ML scoring, SHAP explanations, and audit logging are 100% real.

📊 Dataset Calibration

Synthetic data (20,405 transactions) calibrated against NRF 2024 benchmarks: fashion returns 28-35%, electronics 7-12%. Our Wardrober archetype (40-70% return rate) matches documented wardrobing patterns. The Loyal High-Frequency hard negative was explicitly engineered to prevent trivial threshold-based separation — forcing multi-feature learning. No real customer data was used or scraped.

🔮 What We'd Build Next

Peer-Group Normalization: Z-score vs. category baseline (10% electronics returns is suspicious; 10% fashion is normal).

Device Graph / Abuse-Ring Detection: Shared device fingerprint lookup catches mule rings that a per-transaction score misses (inspired by RiskLens).

Rolling Burst Detection: Flag when refund rate spikes vs. its own 6-hour baseline, not a fixed global threshold.
